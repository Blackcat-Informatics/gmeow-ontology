# Attributed premise echoes and declared textual cues

`echoesPremiseOf` relates an answer information object to the concrete `Prompt`
whose premise a refiner reads it as merely restating. Retain the refiner's
`accordingTo` on the RDF 1.2 assertion or its reifier and keep the answer's
authorship separately. The existing `Refinement` records `observedFeature`,
`vantage` and the selected `observationResult`. A dependence reading asserts
neither falsehood nor independent corroboration (Principles 3 and 9).

## A reviewed release and its declarations

A `CueLexicon` is an immutable reviewed release of `Cue` resources linked by
`hasCue`. Empty reviewed releases remain legal. Each actual cue supplies
`detectionGuidance`, at least one `cuePhrase` or `cuePattern`, and exactly
one target through either `cueEvidenceFor` or `cueEvidenceAgainst`. Both
matching alternatives may coexist; neither receives priority. The named target
is the resource describing the reading, never the reading asserted as a fact.

`detectionGuidance` is the judge's rubric; the detector does not execute it.
`cueExample` and `cueCounterExample` are synthetic illustrations, not
executed detector results or evidence about a real person. Descriptions reuse
`description`. Language uses `writtenInLanguage` and first-class
`Language` resources; registry codes remain `languageCode` alignments on
those resources. Language-tagged and directional RDF 1.2 strings retain their
complete literal identity.

| Release relation | Preserved information |
| --- | --- |
| `versionOf` | Stable lineage, distinct from the immutable release. |
| `versionLabel` | Supplied release designation, without inferred ordering. |
| `contentDigest` | Algorithm-labelled digest of the exact released payload. |
| `wasDerivedFrom` | Original source records. |
| `wasAttributedTo` | Authorship or accountability for the inventory. |
| `cueReview` | Completed sign-off activity for that exact release. |

A sign-off retains `wasAssociatedWith` for the responsible reviewer and
`eventTime` for its actual instant. Multiple sources, reviewers and digest
algorithms can coexist. Any changed cue declaration, text, language, direction,
guidance or scope changes the released payload and requires a new release and
review. Declaration validation neither executes a review nor recomputes a digest.

## Exact comparison contracts

Phrase words are maximal runs of Unicode 16.0.0 general-category letters
(Lu, Ll, Lt, Lm, Lo), decimal digits (Nd), and U+0027 apostrophe. U+2019
participates as U+0027 for comparison only. Combining marks and other characters
are separators; this deliberately declared word rule is not UAX 29 word
segmentation. Tokenize both phrase and source before comparison. Compare a whole
contiguous sequence of tokens, using the equivalence classes generated by the
Unicode 16.0.0 simple C/S case-fold pairs and their symmetric/transitive closure.
There is no locale tailoring, full F mapping, stemming or other normalization.
Separators between tokens may differ. A phrase with no token is malformed.

Keep the original text unchanged. A phrase occurrence spans the first token's
inclusive start through the last token's exclusive end, including original
separators. Matching alternatives form a union: retain one occurrence per
identical cue, source literal and original half-open code-point interval.
Do not merge occurrences from different literals, language/direction tags,
records, fields or source versions.

Patterns use the lang-owned `gmeow:linearRegex` datatype, version one:
Rust regex 1.13.1 with regex-syntax 0.8.11, its Unicode 16.0.0 tables,
default string-regex flags except explicit inline overrides, and leftmost-first
non-overlapping matches. Regex input is the original text; phrase apostrophe
replacement and folding are not applied to it. Any pattern capable of a zero-width
match on any input is malformed; testing only the empty input is insufficient.

The Rust bound is O(m*n) for each individual search, linear in text length n
for fixed pattern size m. Enumerating leftmost-first matches can take O(m*n*n).
The datatype name does not promise linear total enumeration. These are explicit
design choices resolving the phrase and dialect contract; they do not claim that
ontology validation runs a parser, matcher or complexity proof. A selected
operation missing those capabilities fails explicitly.

## Reading scope and negation

`cueReadsWordsOf` selects attributed speaker identities and `cueReadsField`
selects declared property IRIs. Multiple values in either dimension form an
allowed set; the two dimensions both apply when present. Absence means no
restriction in that dimension. Do not infer speaker attribution from a detector,
reviewer, record owner or quoted text. Retain a source record, field, exact literal,
source version and original offsets before comparing occurrences.

`negatedBy` links a target cue to independent `CueNegation` rules. Each rule
has exactly one `negatingCue` and one member of the closed `NegationScope` set:

| Value | Required comparison |
| --- | --- |
| `negationSameSentence` | Both complete spans in one default UAX 29 sentence segment, Unicode 17.0.0, in the same exact source literal. |
| `negationSharedSentence` | Both spans overlap at least one common default UAX 29 sentence segment, Unicode 17.0.0, in the same exact source literal. |
| `negationSameMessagePart` | Same retained `BodyPart` identity, with actual `hasBodyPart` membership. |
| `negationSameMessage` | Same retained `Message` identity, potentially across parts or fields. |
| `negationSameTurn` | Same explicitly supplied source turn identity and source membership evidence. |
| `negationWithinWords` | Same exact source literal and symmetric intervening-word distance at most `negationWindow`. |

A word-window rule carries exactly one positive-integer `negationWindow`;
other scopes carry none. Count whole phrase-rule word tokens entirely between
the original spans. Overlapping or adjacent spans have distance zero, as does
a gap containing only separators. The bound is inclusive and applies in both
directions. Do not substitute bytes, grapheme clusters or UAX 29 word boundaries.

The sentence contract uses Unicode 17.0.0 separately from the Unicode 16.0.0
word/folding contract. A span crossing a sentence boundary fails same-sentence
scope. The alternative `negationSharedSentence` counts a crossing occurrence in
every sentence segment it overlaps. For original match interval `[a,b)` and
sentence interval `[s,e)`, overlap requires `a < e` and `s < b`; endpoint contact
alone does not count. Both matches must overlap the same actual segment in the
same exact source literal. Keep each occurrence and its original interval intact;
sentence participation neither splits nor duplicates `CueMatch` reports. These
scope choices preserve the phrase tokenization and folding contract above.
A thread, timestamp or reply chain does not establish a message or turn.
Missing grouping identity or segmentation capability is unsupported evaluation,
never a silent finding that no suppressor exists.

Suppression uses detected matches before any suppression decision. It has no
recursive cancellation or inferred priority; a suppressed negator remains a
detected negator. Coincident occurrences are not implicitly excluded. Keep every
applicable suppression reason and keep the target occurrence reportable.
Suppression neither reverses evidence polarity nor judges the speaker.

## Intrinsic validation and ordinary source example

Canonical restrictions and realized `logic:Constraint` formulas check required
paths, language, field-property identity, polarity choice, class-local maximum-one targets, finite
scope membership, positive conditional windows and record predicate allowlists.
Closed-record formulas use `logic:linkVia` plus `logic:termIn`; no shape
surface is authored. Their allowlists admit each record's declared fields plus
type, labels/comments, description, source attribution and provenance.
Lexicon releases also admit their version/digest/review fields, `supersedes`
and `writtenInLanguage`; cues admit language and version/digest metadata.
Independent RDF 1.2 statement reifiers may retain richer attribution.

This validates declarations, not actual matches, source grouping, lexical regex
membership or linguistic interpretation. A matcher must preserve all those
contracts independently. Existing code-point `spanStart`/`spanEnd` and
`lang:SurfaceAnchor` remain available for source anchoring without equating
a cue with an analyzed lexical form.

The [review scene](examples/review-and-echo.ttl) references the new
[version two declaration payload](examples/cues-v2.ttl), including French and
directional Arabic, paired phrase/pattern alternatives, and sentence/window
negation declarations. The digest covers that payload's exact UTF-8 bytes,
including its final newline. The scene retains the earlier artifact's identity
and digest rather than rewriting the prior release. It claims no executed
matching, suppression or review.

## Retained occurrences and evaluation inputs

A `CueMatch` reports one detected occurrence using `matchedCue`, the actual
`matchRecord` and `matchField`, and one complete `matchSourceLiteral`. The last
property specializes `lang:literalValue`: preserve lexical form, datatype,
language and RDF 1.2 base direction, including when a source field has several
literals. The source-membership law joins that complete RDF term to the actual
record and predicate. It does not replace the literal with its `STR` value,
force a Document or SurfaceForm type, or invent a source anchor.

Reuse zero-based `spanStart` and `spanEnd` as a nonempty half-open interval in
the original literal's Unicode code points. Supply both as explicitly typed
`xsd:nonNegativeInteger` values. Do not use bytes, UTF-16 units, grapheme
clusters or offsets into normalized text. Numeric order is checked; the required
end-within-original-literal-length bound and authentication of the selected
substring remain consumer matching contracts, not capabilities supplied by
these structural laws.

`matchSuppressedBy` names every applicable `CueNegation` declaration from the
matched cue's `negatedBy` set. Retain any actual negating-occurrence evidence
through `wasDerivedFrom` on the RDF 1.2 suppression assertion or its reifier.
This keeps the rule and the occurrence distinct. Declaration membership does
not prove that a negator actually existed or satisfied the declared scope.
`matchGrounding` independently reports exactly one of `verdictHeld` and
`verdictNotHeld`; a suppressed occurrence may still be grounded. Retain the
detected report in either state. An execution failure is not a not-held result.

A `CueEvalCase` selects one `evalCue` and one complete language-bearing
`evalText`, accepting both ordinary and directional RDF 1.2 language strings.
`evalMatch` retains all reported occurrences for that cue and exact literal,
including suppressed and ungrounded reports. The set may be empty. Its members
must agree with the case's cue and complete literal; their `matchRecord` remains
the actual source and need not be the case. These links do not certify that an
external detector reported every occurrence.

## Attributed detector judgements

`CueJudgement` is an `Observation` SubKind with explicit required `vantage`
and exactly one `cueVerdict`. Use the existing held, not-held and undetermined
values through this dedicated property; generic `evaluationVerdict` belongs to
ConditionEvaluation. The judging vantage remains independent of source
authorship and can include joint agents or standpoints. No new functionality
restriction is imposed on `vantage`.

Choose exactly one target branch. A reported-match judgement uses `judgedMatch`
and carries no judgement offsets, because its target already retains its span.
A missed-occurrence judgement uses `judgedCase` and supplies both nonempty
half-open offsets into that case's `evalText`. Both target properties specialize
`observedFeature`, so the observed subject is the report or case, never a
diagnosed source person. Judgements assess the detector against the cue's
guidance; disagreement can coexist as separate attributed observations.

Record predicate allowlists admit the declared report fields, standard
descriptions, attribution and supplied version/digest/source provenance;
judgements also admit ordinary observation time, method and result. Richer
occurrence evidence can remain on separate RDF 1.2 statement reifiers. When
supplied, retain the exact cue release and original source artifact/version
identity through their existing owners. A digest of a match report does not
identify its input, and the model introduces no mandatory artifact subsystem.

The [ordinary declaration scene](examples/matches-and-judgements.ttl) retains
a suppressed grounded report, an ungrounded report, their shared multivalued
source field, and both judgement branches. It references the unchanged version
two cue payload and review scene. These are synthetic declarations, not executed
evaluation results or an executable case suite.

Canonical laws check field/source membership, offset order, declared suppression
applicability, case/report agreement, judgement branches and closed record
predicates. They do not execute detection, grounding, segmentation or suppression,
authenticate substring offsets, or prove external inventory completeness. A
selected operation requiring those capabilities must supply them or fail
explicitly; a successful declaration check cannot replace them (Principles 4,
9, 11 and 17).

## Selected grounding rules and operational records

`GroundingRuleSet` names a nonempty collection of actual `logic:Rule` members
through `groundingRule`. These carry native RDF 1.2 reified heads and positive
or negative body atoms, not prose-only instructions. A cue may select at most
one set through `cueGrounding`; it is not required to select a set. The selected
operation must compile and evaluate every required member or fail explicitly.
Set membership is not execution, and a set is not a `ReasoningProgram`, whose
query, evaluation mode and sorted-variable contracts remain separate.

Rule declarations can be loaded globally. Each rule of the supplied
`operationalCueGrounding` policy therefore positively checks both its own
`groundingRule` membership and `groundingSelectedBy(set, reader)` before
deriving anything. This separate selection input does not grant authority or
claim that execution occurred. `cueGroundingReader` identifies the actual reader
of a match whose cue declares a grounding set, with a local maximum of one.
Unrelated matches acquire no unconditional reader requirement. Keep separate
reports for independently grounded readings of the same source occurrence.

The reader supplies `machineryAdmittedBy` only for actual operational-record
admissions. Preserve its standpoint and statement provenance separately from
source authorship. An attempt can be human; an event kind, a SoftwareAgent type
or a `derivedBy` assertion cannot supply admission or identify an author.
The declared policy derives `machineryForReader(record, reader)` only through
these finite relation choices:

| Rule family | Required source and admission |
| --- | --- |
| Attempt root | An actual Event with `eventTypeAttempt` and explicit admission. |
| Intention-transition roots | An actual Event with one of the five agency transition kinds, an actual `intentionTransitionOf` Intention and explicit admission. |
| Event descendants | `subEventOf` to a reader-specific machinery Event, with the same reader's admission at both ends. |
| Generated information records | An InformationObject with `wasGeneratedBy` a reader-specific machinery Activity, with the same reader's admission at both ends. |

`subEventOf` is transitive: a descendant may be nested several containment
levels below an admitted root. The finite policy selects relation kinds, not a
single physical hop. `used`, `readArtifact`, `receiptArtifact`, `wasDerivedFrom`
and `derivedBy` do not propagate the role. Even an actual generated output needs
its own admission, preserving human-authored drafts and original source words.
Tool calls and operation receipts remain activities, not information objects.
`logic:EffectAttempt` is an externally dispatched enactment record and is not
a substitute for the agency owner's prose attempt event.

`MachineryRecord` is a cross-kind Mixin. A separate rule can publish that unary
type from derived reader-specific state, but no recurrence or negative grounding
guard reads the unary type. Both propagation and exclusion retain the same
reader coordinate, so one reader's classification cannot decide another's
result even when their facts coexist. Select the actual input world and the
reader's operation facts before evaluation; do not union independent worlds
or different policy evaluations and present them as one completed reading.
Retain or derive the owning Event, Activity, Intention and InformationObject
type facts required by these rules. A graph-free evaluator does not acquire
ontology closure merely by receiving a ToolCall type. If a selected operation
needs that closure and cannot supply it, fail explicitly before the negative
stratum rather than silently treating an unclassified record as eligible.

The final policy rule binds the match's actual cue, source record, field and
reader, together with the cue's active selected set. After positive machinery
closure, it derives `cueGrounded(match, cue)` when that same reader's machinery
state is absent from the completed selected interpretation. This is eligibility
under this specific exclusion policy, not proof of human authorship or a verdict
about the speaker. Other policies may supply other real grounding rules. The
derivation does not change suppression, evidence polarity or source text.

`cueGrounded` and `machineryForReader` are derived outputs, never source inputs;
unary `MachineryRecord` publication likewise belongs to the derived result.
Keep source facts and derivations distinct and retain selected set, reader and
world evidence. A reported `matchGrounding` value does not itself derive
`cueGrounded`. The binding law checks an actual grounded fact against the same
matched cue, selected reader/set and reported held outcome. Ordinary union-graph
integrity cannot authenticate source-versus-derived origin or execution
completion; no such admission checker or executor is introduced here.

Required membership, local cue/reader maxima, real reifier evidence and closed
set fields are canonical declaration contracts. The existing closed cue and
match records admit their grounding fields, and closed records admit explicit
operational admission/state metadata. Full AST validity, supported rule
capabilities, stratification and complete selected evaluation remain with the
canonical compiler and selected native operation. Missing inputs, capabilities
or incomplete evaluation must fail rather than turn silence into a negative.

The [ordinary selected-grounding scene](examples/selected-grounding.ttl) retains
an unadmitted human attempt, an admitted operational attempt and tool call, an
input read and two differently admitted outputs. It preserves the writer and
original literals and records two illustrative match outcomes. It asserts no
derived machinery or grounded fact and claims no executed evaluation. Existing
released cue payloads remain unchanged; no input artifact identity or digest is
fabricated (Principles 4, 9, 11, 17 and 19).

## Reviewed reading parameters

`ReadingRule` names an immutable parameter release, separate from its lineage,
the versioned reader and a `logic:Rule` executable AST. Reuse `versionOf`,
`versionLabel`, `contentDigest` and `wasAttributedTo`. The release and its
lineage are distinct. A changed parameter or declared word inventory requires a
new release; existing versions are retained. Numeric parameters are reviewed
source vocabulary, not hidden implementation defaults.

A generic rule may explicitly declare `minimumRun` and `minimumShare`.
A run threshold is a positive integer; a share threshold is decimal, strictly
greater than zero and at most one. Their absence does not authorize a consumer
to invent a default. The selected rule contract determines which parameters it
uses.

`RestatementRule` specializes `ReadingRule` and requires
`restatementMinimumRun` and `restatementMinimumUncommonWords`.
The first specializes `minimumRun`. The uncommon-word threshold is nonnegative:
zero is a deliberate setting, not a missing capability. A source shorter than
the minimum run can qualify through whole-source repetition only under the
declared uncommon-word condition. No implicit minimum-share threshold or
unrequested relationship between the two integer thresholds is imposed.

`restatementCommonWord` retains each machine token spelling exactly as the rule
reads words, using strings rather than token whitespace normalization. The
inventory is unordered and may be empty. Keep declared language and matching
semantics on the version; do not invent a language, tokenizer, case fold,
`Lexeme` or normalization pass from the string alone. Cue lexicons remain
separate reviewed artifacts a reader may use alongside these parameters.
These declarations do not execute a matcher.

## Possible restatements and measured echoes

The restatement reading is the existing `wasDerivedFrom` relation from the
later text to its outside source. Retain it through explicit RDF 1.2 reification
and `accordingTo`; use the canonical `standpointModalForce modalForcePossible`
axis. A measured restatement carries no `confidence` or numeric
`standpointCredence`. Its `restatementRun` is a positive-integer longest
consecutive run, and `restatementShare` is decimal coverage of the outside
source's words in (0, 1]. These are ranking measurements, not probabilities or
independent support.

`echoRun` and `echoShare` instead qualify the exact `echoesPremiseOf`
reading between an answer and its concrete `Prompt`. The run is the longest
prompt-word sequence repeated in order within one answer sentence. The share
uses the answer's words as denominator. It is distinct from outside-source
coverage and need not equal a ratio derived from that sentence's longest run.
Both measures are supplied results, never computed or calibrated by these laws.

The canonical reifier contracts require complete measurement pairs, original
text bindings and a reader. Restatements also retain receipt time, basis and
rule-version digest. Every annotation concerns its own exact statement
predicate, subject and object through the existing lowered statement components.
Consume type closure and completed statement-metadata lowering before these
checks; a neighboring statement cannot supply a missing source or prompt.
Quotation alone does not assert its content as a global fact.

`restatementRuleVersion` keeps the exact digest RDF literal supplied on the
actual immutable `RestatementRule` release linked through `wasDerivedFrom`
on the reading reifier. Its graph-term join preserves lexical form and datatype.
The parameter digest identifies the declared release; it is not a version label
or a new token datatype. These declarations neither compute a hash nor supply
missing native digest admission. A selected operation still requires its
declared digest capability; no weaker validator is substituted. The ordinary
scene retains a producer-supplied digest without claiming independent byte or
algorithm verification.

## Retain receipt interpretation

`restatementReceivedAt` is the supplied date-time in the reader's receipt
ordering. Preserve the original precision and timezone evidence; do not pad a
coarse value or repair incomparable clocks. `ReceiptBasis` is an open
`QualityValue` vocabulary, not a source artifact or observation result.

The supplied bases distinguish message `receivedAt`, the latest supplied
assertion time of acts named by the outside claim's evidence, and the outside
claim's own assertion time. Their definitions preserve the reader's reported
absence of a stronger receipt source. The message clock is storage receipt,
not proof of human readership. No basis value automatically selects a fallback,
calculates a latest time, proves earlier receipt or imposes a universal
preference. Retain the actual source evidence and the selected reader's
ordering contract separately.

The [ordinary rule and reading scene](examples/reading-rules.ttl) retains
immutable parameters, possible restatement, echo measurements and explicit
empty-computation reports. Its declarations are synthetic source data, not
executed word matching or authenticated computation.
