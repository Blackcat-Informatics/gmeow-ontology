    GMEOW GTS Transport Module¶

    The GMEOW GTS Transport Module — classes, properties, and individuals of the GMEOW super-vocabulary.

    IRI: https://blackcatinformatics.ca/gmeow/slices/gts
    CURIE: gmeow:slices/gts

    Type: owl:Ontology

    Transport/packaging vocabulary so GMEOW can DESCRIBE and dogfood its own transport: a GTS file (docs/GTS-SPEC.md) as a first-class entity — its segments, profiles, chain heads, transform codecs, opaque (sealed/undecodable) frames, and compaction lineage.

    MODEL BOUNDARIES (Principles 1, 9, 12). - GTS gives TRANSPORT claims (these bytes, this order, this chain); GMEOW gives CONTENT claims (this statement is true, according to whom). A frame signature or head commitment is an Attestation whose attestedSubject is a GTSSegment; it proves bytes/order/signer key control, never the truth of the carried statements (#342). - Compaction re-authors only the ORDERING: content claims ride as ordinary quads and are rewrite-invariant by construction; transport claims over the old chain become detached evidence about the source document, cited through the compaction's derivation lineage. - Fold semantics, codec reversal, hash verification, and signature checking live in the solver layer (the gts engines); this module only describes their artifacts and outcomes.

    REUSE (no parallel mechanisms — #267). - Byte identity of blobs and files -> gmeow:contentDigest (sources). - Chain-head identity of a segment -> gmeow:gtsHeadId, a versionFingerprint (versions). - Frame/head signatures, signers -> gmeow:hasSignature / gmeow:Attestation (attestation). - Compaction and production lineage -> gmeow:wasGeneratedBy / wasDerivedFrom (provenance). - Suppress frames -> gmeow:displayable (kernel, P10) — suppression is a display overlay, never erasure, in the format AND in the ontology. - annot-frame standpoints -> gmeow:accordingTo / standpointModality (standpoint). - Media payloads -> gmeow:MediaObject (documents) carried as blobs.
