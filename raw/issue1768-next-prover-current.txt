# Issue #1768: feat: add a first-class consumer prover entry point

State: OPEN   Repo: Blackcat-Informatics/gmeow-ontology   Forge: github

## Body

## Problem

GMEOW has a capable native prover and a TPTP projection, but a consumer currently has to understand the internal `logic:Formula` / `logic:relation` / indexed `logic:TermCarrier` encoding to make an assertion visible to proof. #1755 demonstrated the failure mode: plausible domain triples are accepted as RDF but never enter the logical carrier, so an intended obligation can be silently unenforced.

We need one obvious installed-binary path for asking GMEOW to prove a claim. This is a public consumer operation under the CLI razor: it must work from `gmeow` plus the embedded `gmeow.gts`, with no repository checkout or developer pipeline.

## Scope

Add a first-class `gmeow prove` surface and matching library API that:

- always loads the complete embedded `gmeow.gts` canon as the immutable base theory, then layers the caller's compact, typed premises and goal onto it without requiring callers to hand-assemble RDF list/formula carriers;
- lowers that request once into the canonical native `logic:` formula representation and runs the native prover;
- can emit the exact TPTP-FOF problem for external proof tooling, reusing #1751 rather than creating a second exporter;
- returns a stable machine-readable verdict with proof/evidence references, standpoint, provenance, loss evidence, and the logical stage contract;
- detects ordinary domain triples that appear intended as proof premises but lack a certified correspondence/lowering, and fails with an actionable diagnostic instead of silently ignoring them;
- uses registered typed correspondence laws when domain vocabulary is admitted into logic, without treating bounded-corpus success as authority for unrestricted rewrites.

## Acceptance criteria

- `gmeow prove REQUEST` works from the installed consumer binary and always reasons against the complete embedded GMEOW bundle; there is no module-selection path that can silently omit canon axioms.
- Every verdict records the exact embedded bundle identity and preserves evidence/provenance links into that canon.
- A documented minimal request can express the navigation obligation from #1755 and receives the expected rejection/proof result.
- The equivalent canonical carrier request yields the same verdict and evidence.
- An unlowered domain-triple version fails explicitly and explains how to supply or select the required correspondence; it cannot produce a misleading success.
- Native execution and TPTP export share the same lowered request and symbol table, with no serialize/reparse round trip.
- Output supports a deterministic JSON form suitable for applications, plus concise human output.
- Product tests cover GMEOW request lowering, verdicts, diagnostics, and evidence. They do not duplicate PurRDF RDF/SPARQL/GTS conformance tests.
- Documentation includes one copy-paste CLI example and one library example.

Implementation audit before mutation:

Already present on `main`:
- the public `gmeow prove` command and bounded E/Vampire protocol;
- an embedded `gmeow.gts` and embedded GMN codebook;

Confirmed gaps:
1. `prove` currently compiles only caller-supplied RDF. It never loads the embedded canon, so the executable contains the theory but the proof operation does not use it.
2. `make cli-build` is documented as the consumer build entry point but merely depends on `producer-build`; a clean tree still lacks the bundle/codebook. `make install` works only because it performs sync beforehand.
3. The bundle has a guarded build-time path; the GMN codebook is embedded through an unguarded source-tree-relative path.
4. Existing self-sufficiency coverage exercises `info` and `transpile`, not the staged `dist/bin/gmeow prove` path.

Implementation slice:
- compose the authenticated embedded canon with caller inputs in memory before the single logic lowering, and record the exact bundle identity in the proof receipt;
- guard and override both embedded asset paths in `build.rs`, while retaining one executable and no runtime asset directory;
- split the internal already-materialized consumer build from the public source-first `cli-build` target so `install` still invokes the producer exactly once;
- add a staged-binary proof acceptance from a blinded cwd with an empty environment and an absolute stub-prover path, proving the executable requires no checkout/generated directory at runtime;
- update consumer docs and Make contract tests.

The existing typed-request/native-prover and ungrounded-domain-triple diagnostics in the issue remain broader semantic work unless they are already exposed by the current lowering. This slice fixes the critical distribution failure and the discovered canon-omission bug without creating a second proof implementation. Principles 4, 7, 12, 17, 18, and 19 govern the change.
