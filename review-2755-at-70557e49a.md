## Required findings

### REQUIRED 1: `crates/pipeline/src/node.rs:163-166` (`StageProduct::carrier_released`) attributes a release to the wrong condition
- Quoted: "...once the LAST stage whose dataflow edge from this one declares a carrier read has run (...), or when the product is handed to a consumer whose edge declares no carrier read, under [`CarrierRetention::DropAfterLastConsumer`](crate::scheduler::CarrierRetention)."
- Code: `scheduler.rs:741-747`. The release on hand-over happens for any product whose consumer is not a carrier reader (`whole` is false), under the enforcing read policy, whatever `carrier_retention` is. `RunContext` constructors default to `RetainAll`, and the release still happens there; `tests.rs` `CarrierStage` relies on it. Only the "last carrier reader has run" release is under `DropAfterLastConsumer`. The new `bundle.rs:164-166` text states the hand-over release correctly ("under the enforcing read policy"), so the two docs now disagree.
- Origin: in the 68272e7e4 diff, so I should have caught it in the sweep. It is not introduced by the delta.
- Corrected: "...once the LAST stage whose dataflow edge from this one declares a carrier read has run, under [`CarrierRetention::DropAfterLastConsumer`](crate::scheduler::CarrierRetention); and, under the enforcing read policy whatever the retention, on the copy handed to a consumer whose edge declares no carrier read."

No other required finding. I did not find a new false, self-contradictory or misleading statement in the changed lines or their neighbours, and I found no remaining false statement of the swept kinds in the text this PR adds or changes against main 04aa28a7e, apart from REQUIRED 1.
