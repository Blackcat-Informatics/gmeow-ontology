# GMEOW → LPG Mapping Specification

> **The load-bearing design document for the RDF → Property Graph projection.**
>
> GMEOW is RDF 1.2 / RDF\*-first (CONSTITUTION Principles 2–3). The LPG export is
> where that design pays off: statement metadata (confidence, provenance,
> temporal scope) becomes **native edge properties**, and coexisting
> standpoint-indexed claims become **parallel multi-edges** — both natively
> expressible in property graphs, unlike plain RDF.

---

## 1. Philosophy & Scope

The LPG export is a **deliberately lossy, directional projection** (Principle 4).
It is a data view, not a reasoner. What drops is declared; what maps is
information-preserving.

- **Canonical source:** ontology slices + `dsl/statements/` (compiled natively to
  `statements/gmeow.rdf12.ttl`).
- **LPG consumer:** `dist/lpg/` — generated by `gmeow export lpg`, drift-checked
  (`--check`), never hand-edited.
- **Engine:** `purrdf` produces and parses the canonical RDF 1.2 artifact
  natively; Jena remains an oracle-lane cross-check only.

## 2. Resource → Node

Every RDF resource (URI or blank node) that appears as a subject or object in a
non-dropped triple becomes an LPG node.

| RDF | LPG | Notes |
|---|---|---|
| Resource URI | Node `:ID` | CURIE when possible (`gmeow:Person`); full URI otherwise. Stored also as `uri` property. |
| `rdf:type` | Node `:LABEL` list | Every type assertion adds a label. Also stored as `types` list property. |
| Blank node | Dropped (default) | Filtered by default; only OWL-restriction blanks are present in source TBox, not domain entities. See §8. |

Nodes carry **no OWL TBox** — no restrictions, no cardinality, no equivalentClass.
Those are reasoning constructs; the LPG is an ABox data view.

---

## 3. Datatype Property → Node Property

A datatype property assertion `s p "v"^^xsd:T` becomes a node property on the
node for `s`.

| RDF | LPG | Notes |
|---|---|---|
| Predicate URI | Property key | CURIE-shortened (`gmeow:name` → `name`). |
| Literal value | Property value | XSD types coerced to JSON/Python scalars (`xsd:integer` → `int`, `xsd:boolean` → `bool`, `xsd:dateTime` → ISO string). |
| Language tag | `lang` suffix or separate property | `"hello"@en` → `{"value": "hello", "lang": "en"}` or key `value@en` depending on target format. |

---

## 4. Object Property → Relationship

An object property assertion `s p o` becomes a directed edge from the node for
`s` to the node for `o`.

| RDF | LPG | Notes |
|---|---|---|
| Predicate URI | Relationship `:TYPE` | CURIE-shortened (`gmeow:from` → `from`). |
| Subject | `:START_ID` | |
| Object | `:END_ID` | |

---

## 5. Statement Metadata → Edge Properties (Headline)

This is where GMEOW's RDF-1.2-first design pays off. In the canonical RDF 1.2
artifact, a base triple `s p o` may carry metadata on its reifier:

```turtle
<<( :s :p :o )>> :confidence 0.95 ;
                :assertedAt "2026-01-15"^^xsd:dateTime ;
                :validFrom "2026-01-15"^^xsd:dateTime ;
                :accordingTo :standpointA .
```

In the LPG, the edge `s --[p]--> o` carries these as **native edge
properties**:

```cypher
(:s)-[:p {confidence: 0.95, assertedAt: "2026-01-15",
           validFrom: "2026-01-15", accordingTo: "standpointA"}]->(:o)
```

This is a 1:1 mapping — no information loss. The layer that is a downcast
burden in OWL 2 DL becomes first-class in LPG.

## 6. Standpoint-Indexed Contested Claims → Parallel Multi-Edges

When multiple standpoints assert the same base triple with different metadata,
GMEOW represents them as **coexisting, non-privileged claims** (Principle 9).

In RDF 1.2:

```turtle
<<( :s :p :o )>> :confidence 0.95 ; :accordingTo :standpointA .
<<( :s :p :o )>> :confidence 0.70 ; :accordingTo :standpointB .
```

In the LPG, this becomes **two parallel edges** — none privileged:

```cypher
(:s)-[:p {confidence: 0.95, accordingTo: "standpointA"}]->(:o)
(:s)-[:p {confidence: 0.70, accordingTo: "standpointB"}]->(:o)
```

Each edge carries its own `accordingTo` and `confidence`. There is no
"primary" or "preferred" claim (Principle 9).

## 7. Reified Relator → Intermediate Node

GMEOW's relators (`gufo:Relator` — NameUsage, Participation, Membership,
StandpointTenure) are reified entities that carry their own properties and
participants. In the LPG they become **intermediate nodes** (lossless default):

```cypher
(:Person)-[:hasNameUsage]->(:NameUsage_1)
(:NameUsage_1)-[:nameValue]->(:Name)
(:NameUsage_1)-[{periodStart: "2020-01-01", periodEnd: null, confidence: 1.0}]
```

An optional **flatten-to-edge** convenience (documented as lossy) copies
relator properties onto a direct edge:

```cypher
(:Person)-[:hasName {nameValue: "Alice", periodStart: "2020-01-01"}]->(:Name)
```

The flatten mode loses the relator's identity (you cannot attach further
metadata to the relator node). It is a convenience, not the default.

## 8. Documented Drops

The following RDF constructs are **intentionally dropped** — the LPG is a data
view, not a TBox reasoner:

| Dropped Construct | Reason |
|---|---|
| `owl:Restriction` (allValuesFrom, someValuesFrom, cardinality) | TBox reasoning construct; not instance data. |
| `owl:equivalentClass`, `owl:equivalentProperty` | TBox equivalence; LPG has no inference. |
| `rdfs:subClassOf` (class hierarchy) | TBox; node labels carry `rdf:type` only. |
| `owl:disjointWith`, `owl:propertyChainAxiom` | TBox / reasoning constructs. |
| `owl:imports` | Document-level metadata; irrelevant to instance graph. |
| RDFS / SKOS annotations (`rdfs:comment`, `skos:note`) on TBox terms | Ontology documentation; not instance properties. |

## 9. Format-Specific Notes

### Generic CSV (`nodes.csv` + `edges.csv`)

- Flat, portable, no vendor typing.
- `nodes.csv`: `id,label,uri,types,...properties`
- `edges.csv`: `id,source,target,type,...properties`

### Neo4j Admin Import CSV

- Typed headers: `:ID`, `:LABEL`, `:START_ID`, `:END_ID`, `:TYPE`.
- One node file per label group; one edge file per relationship type.

### openCypher (`gmeow.cypher`)

- `CREATE` / `MERGE` statements compatible with Neo4j, Memgraph, Kuzu.
- ISO GQL converging.

### GraphML

- XML for Gephi, igraph, networkx.
- Nodes carry `<data>` elements for properties; edges carry `<data>` for edge
  properties.
