## Required findings

### REQUIRED 1: the `ReadPolicy::Enforce` doc states a behaviour the scheduler does not have

`crates/pipeline/src/reads.rs:237-238`: "A stage that reads what its edges do not declare, or does not read what they declare, fails and publishes nothing. Every production run."

This is false. In the scheduler's `commit_result` path the product is still inserted (`products.insert(run.id, run.product)`) and dependents are readied. Only `cache.put` is skipped (`!reads_differ`), and the run fails at the end. The slice `flowReadsLane` definition already says the true thing ("The stage's product is still published ... not written to the stage cache"), so the doc and the slice now disagree. It sits directly above the `Record` doc that 68272e7e4 corrected, so the same statement-accuracy class as R2 is still wrong one line higher.

Disclosure: this text is not in the 68272e7e4 delta and I missed it in my dbbd77181 review. It is a pre-existing false statement in a file the PR rewrites, and it is the same class as R2.

Fix: say the stage fails the run and its product is not written to the stage cache. Do not say it publishes nothing. Alternatively, change the behaviour; the doc fix is the smaller change.

### REQUIRED 2: the `bound_production_stage` doc claims an instance it does not return

`crates/pipeline/src/run.bound_stage_tests.rs:6-7`: "the same instance the scheduler runs".

The helper calls `bind(&full_spec() ...)` with `default_registry()` and creates a fresh binding. It is an equivalent binding, not the instance a run uses; production binds with `registry_for(profile)` and `spec_for_scope`. The claim matters because the four tests that use it assert on the declarations "the production stage reports". Say "the stage the authored pipeline binds under the default registry and the full spec" and drop "same instance". This is a one-line text fix.
