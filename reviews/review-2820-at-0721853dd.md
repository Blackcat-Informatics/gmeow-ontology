## Fix 3: admission.rs list-cell bound (bot finding 4)

**Correct.**

No error is dropped:

- The only production caller of `bind_list_cells` is `store`. It maps `Err(n)` to `ListCells::Cut { associations: n }`.
- Both callers of `store` carry the `ListCells` through.
- `close` uses `cells.is_bound()` for eligibility. That is the same boolean as before.
- The four existing tests now assert `.is_ok()`, which matches their old meaning.
- The `checked_*` to `saturating_*` change behaves as before: an overflow saturates past `MAX_BINDINGS` and returns `Err`, where it used to return `false`.

"At least N" is true:

- `rows` accumulates `members[c].len() * known.len()` per component. That is exactly the number of head/cell rows the publication loop inserts for that component.
- The walk returns at the first component whose running total exceeds `MAX_BINDINGS`. So the reported `total` is the exact count over the components processed so far, and every unprocessed component adds a count of zero or more.
- If the total saturates, the full count is still at least `usize::MAX`.
- "past its bound" holds because `total > MAX_BINDINGS`.

Behavior:

- The only change in behavior is the extra note. `list_cells_bound`, `join_atoms` and `specialize_all` take the same boolean as before.
- The note reaches results through `Settled.notes` and the existing `refused` closure, like the witness-free note.

The evidence-gap path:

- When `specialize_all` returns `Err` and `certify_settled` returns `Ok(Err(gap))`, the notes are discarded. This is not a fault: that gap is itself reported as the bound, and the template decides.
- The witness-free note has always been discarded the same way.
