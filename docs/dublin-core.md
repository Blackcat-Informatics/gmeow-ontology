# Dublin Core — alignment & projection reference

The alignment and projection companion to the GMEOW↔Dublin Core policy.
Everything here is **authored once** in `mapping-dsl/` and generated by
`gmeow-dev sync --mode update --outputs generated` (Principle 4); nothing in `mappings/`, `projections/`, or
`queries/projections/` is hand-edited.

> **Principle 5** (Maximal bridging by reference): GMEOW mints exactly one canonical
> term per concept and aligns it to every relevant surface vocabulary by reference —
> never rewriting anyone else's data.
>
> **Principle 1** (SOTA by being SOTA): Model what *should* have been written. GMEOW
> prefers `dcterms:` over legacy `dc:` and respects the DCMI dumb-down and one-to-one
> principles.

---

## Namespace Semantics

GMEOW uses three Dublin Core-related namespaces. Each has a precise role; mixing them
is a modelling error.

| Prefix | Namespace | Role |
|--------|-----------|------|
| `dcterms:` | `http://purl.org/dc/terms/` | **Primary alignment namespace**. DCMI Metadata Terms — the refined, qualified vocabulary. All GMEOW→DC alignments and projections are authored here first. |
| `dc:` | `http://purl.org/dc/elements/1.1/` | **Derived dumb-down namespace**. The 15 unqualified elements. GMEOW does **not** hand-author `dc:` alignments; they are derived from `dcterms:` via the subproperty hierarchy (`dcterms:X ⊑ dc:X`). |
| `dcmitype:` | `http://purl.org/dc/dcmitype/` | **Type vocabulary**. DCMI Type Vocabulary classes (`Text`, `Dataset`, `Image`, `Sound`, `Software`, `Collection`, `Event`, …) aligned to GMEOW work types. |

### The dumb-down principle

DCMI defines a refinement relationship: `dcterms:created rdfs:subPropertyOf dcterms:date`
and `dcterms:date rdfs:subPropertyOf dc:date`. GMEOW respects this hierarchy:

- `dcterms:` alignments are **authored** in `mapping-dsl/equivalences/`.
- `dc:` alignments are **derived** by the compiler/lint layer, not hand-authored twice.
- The `oai_dc` projection is the explicit, documented dumb-down of the `dcterms`
  projection — refinements collapse to the 15 broad elements.

### The one-to-one principle

GMEOW's reified model (standpoint-indexed claims, relators with temporal scope) already
honours the DCMI one-to-one principle: a `dcterms:creator` edge in the projection is the
flattened view of a reified attribution or name-usage relator, not a confused mix of work
and surrogate.

## Projection profiles

### `dcterms` (qualified DC)

The `dcterms` projection emits rich qualified Dublin Core records from GMEOW's reified
graph. Flat forms are projections of relators; standpoint and temporal structure is
flattened and documented as lossy.

| GMEOW pattern | projected term | lossiness |
|---|---|---|
| `?work gmeow:hasTitle ?title` | `?work dcterms:title ?title` | none |
| `?work gmeow:description ?desc` | `?work dcterms:description ?desc` | none |
| `?work gmeow:hasAuthor ?author` | `?work dcterms:creator ?author` | standpoint/tenure flattened |
| `?work gmeow:hasContributor ?contrib` | `?work dcterms:contributor ?contrib` | role granularity lost |
| `?work gmeow:datePublished ?date` | `?work dcterms:issued ?date` | none |
| `?work gmeow:identifier ?id` | `?work dcterms:identifier ?id` | none |
| `?work gmeow:isAbout ?topic` | `?work dcterms:subject ?topic` | none |
| `?work gmeow:sourceLocation ?src` | `?work dcterms:source ?src` | none |
| `?work gmeow:hasPart ?part` | `?work dcterms:hasPart ?part` | none |
| `?work gmeow:partOf ?parent` | `?work dcterms:isPartOf ?parent` | none |
| `?work (hasTitle\|hasName\|hasAppellation) ?name` ; `?name gmeow:nameLanguage ?lang` | `?work dcterms:language ?lang` | name relator flattened |
| `?work gmeow:hasLicense ?lic` | `?work dcterms:license ?lic` | none |
| Reified copyright → holder | `?work dcterms:rightsHolder ?holder` | relator flattened |
| Reified copyright → notice | `?work dcterms:rights ?notice` | structured rights flattened |
| Reified copyright → year | `?work dcterms:dateCopyrighted ?yr` | relator flattened |

Compiled to `projections/dcterms.edoal.ttl` + `queries/projections/dcterms.rq`.

### `oai_dc` (unqualified 15-element DC)

The `oai_dc` projection is the **dumb-down** of the qualified `dcterms` projection,
emitted for OAI-PMH harvestability. Every refinement collapses to its broader 15-element
`dc:` form.

| Qualified source | Unqualified target | notes |
|---|---|---|
| `dcterms:creator` / `dcterms:contributor` | `dc:creator` / `dc:contributor` | distinction preserved where possible |
| `dcterms:issued` | `dc:date` | all date refinements collapse |
| `dcterms:hasPart` / `dcterms:isPartOf` | `dc:relation` | all relation refinements collapse |
| `dcterms:license` / `dcterms:rights` / `dcterms:rightsHolder` | `dc:rights` | rights refinements collapse |
| `dcterms:spatial` / `dcterms:temporal` | `dc:coverage` | coverage refinements collapse |
| All other `dcterms:X` | `dc:X` | direct element mapping |

`dc:type` is currently reserved: GMEOW has no direct `workType` property (types are
class-based). `dc:coverage` is projected from `gmeow:spatialCoverage`,
`gmeow:temporalCoverage`, and (as a fallback) `gmeow:containedInPlace`.

OAI-DC XML examples are also emitted during `gmeow build` as
`dist/gmeow-example-oai_dc-*.xml` (one file per subject, OAI-PMH harvestable).

Compiled to `projections/oai_dc.edoal.ttl` + `queries/projections/oai_dc.rq`.

## Known gaps (intentional)

The following DCMI Terms have no direct GMEOW equivalent without minting new
ontology terms. They are documented here as intentional gaps per Principle 1
(SOTA by being SOTA) — GMEOW models the concept correctly and bridges when a
suitable term exists, never forcing a weak alignment.

| DC term | status | reason |
|---|---|---|
| `dcterms:publisher` | unmapped | No `publisher` property; PROV-O `wasAttributedTo` covers attribution generically |
| `dcterms:valid` | unmapped | No validity-interval property; `validFrom`/`validUntil` are annotation properties on statements/facets |
| `dcterms:type` | unmapped | Intentionally broad; GMEOW uses class-based typing (`rdf:type`) and `dcmitype:` alignments |
| `dcterms:relation` | unmapped | Intentionally broad; refinements (`hasPart`, `isPartOf`, `references`, etc.) are mapped |
| `dcterms:date` | unmapped | Intentionally broad; refinements (`created`, `modified`, `issued`, etc.) are mapped |
| `dcterms:coverage` | unmapped | Intentionally broad; refinements (`spatial`, `temporal`) are mapped |
| `dcmitype:StillImage` | unmapped | No `StillImage` class; `MediaObject` → `Image` via `relatedMatch` |

## Standards bridged

- **DCMI Metadata Terms** (`dcterms:`) — ISO 15836-2; the refined vocabulary.
- **DCMI Type Vocabulary** (`dcmitype:`) — RFC 5013; type classes for works.
- **Dublin Core 15-element set** (`dc:`) — ISO 15836-1; the unqualified baseline.
- **OAI-PMH** — `oai_dc` mandatory metadata format; the dumb-down projection target.
