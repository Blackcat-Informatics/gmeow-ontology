# Issue #2841: Record the canonical profile beside the bundle and envelope digests

State: OPEN   Repo: Blackcat-Informatics/gmeow-ontology   Forge: github
Labels: enhancement, foundational, cross-cutting, dependencies, rust

## Body

## Why

The shipped bundle and its medium envelope carry digests computed over PurRDF canonical output (the coherence certificate's bundle hash and axiom hashes, the snapshot stratum digest, term definition digests). None of them records which canonicalization profile produced it. A consumer built on a different profile cannot tell a profile change from corruption: `gmeow medium verify` fails with a plain digest mismatch, and a reader cannot select the profile that matches the artifact.

## What

Record one canonical profile identifier and version, plus the flat-assertion presentation identifier and version, beside the digests that depend on them, written from the constants already asserted in `crates/gts-profile/src/canon_profile.rs`:

- the medium envelope (written in `crates/pipeline/src/medium/rdf.rs`, read in the same file and checked in `medium/inspect.rs`), with its terms declared in the owning slice module;
- the coherence certificate payload (`crates/logic/src/certificate.rs`), included in the signed text.

The envelope check compares the marker before the digest and fails with a distinct profile-mismatch error. An artifact without the marker is refused with an actionable message; there is no compatibility path.

Term definition digests live in the term release authority, which has no re-bless mode; their profile is the profile recorded on the bundle that carries them, so that file is not changed here.

## Acceptance

- A bundle produced by `make check` records the marker; `gmeow medium verify` accepts it.
- A bundle with a different marker is refused with a profile-mismatch error, not a digest mismatch (negative test).
- Goldens and snapshots that pin the envelope or certificate are regenerated by their own targets, not by hand.

Depends on the pull request that adds `canon_profile.rs`. Gates release 0.4.0 by coordination decision.

Also in this change: correct the last paragraph of "Values derived from the canonical profile" in `docs/GATE-AND-PIPELINE.md`. By reading, `gmeow prove --check-proof` recomputes the canonical identity of the OWL view and compares it with the proof's recorded input identity. `gmeow medium verify` recomputes canonical RDF only for the snapshot envelope's strata digest of a self-describing bundle; its frame digests are BLAKE3 over decoded bytes. A PACK header also embeds a SHA-256 of its dataset's canonical N-Quads, so a profile change that alters canonical bytes changes pack bytes; the pack dictionary keeps the dataset's own blank-node labels, not canonical ones. The sentence now in the document says both commands recompute canonical digests, which is too broad for `medium verify`.
